# Phase 2.0 — ライブラリ検索 UI のテストリスト

Phase 1.3 で実装した `src-tauri/src/library/query.rs`（検索・整列・集計・
コメント FTS）を、ライブラリ画面 (`src/routes/library/+page.svelte`) へ接続した
ぶんのテストリスト。

UI の状態とクエリ変換は `src/lib/stores/libraryQuery.ts` に切り出してあり、
単体テストは `src/lib/stores/libraryQuery.test.ts`（vitest）に置いている。

## 分/秒の変換

- [x] 分入力 → 秒（`5` → 300 / `1.5` → 90 / `0` → 0）
- [x] 空・非数値・負値は「条件なし」(`undefined`)
- [x] 秒 → 分の逆変換（割り切れない時は小数 1 桁）

## クエリ組み立て (`buildLibraryQuery`)

- [x] 既定状態では並び順とページングだけを送る
- [x] 未指定の絞り込みはキーごと落とす（IPC ペイロードを膨らませない）
- [x] 全条件指定 → `query.rs` のパラメータ名へ写像（`minMinutes` → `minDuration` 等）
- [x] `isShort=false` は「絞り込みなし」なので送らない
- [x] `tags` は状態の配列を共有しない（呼び出し側の破壊的変更が漏れない）
- [x] `offset` = ページ番号 × 表示件数
- [x] UI に出す並び順は `query.rs` の `ALLOWED_SORT` の部分集合

## 状態更新 (`patchLibraryFilter` ほか)

- [x] `page` 以外を変更したらページを 0 に戻す（3 ページ目で条件を変えて 0 件に見える事故の防止）
- [x] ページ送りだけならページを保つ
- [x] 明示的な `page` 付きパッチはその値を採用する
- [x] 元の状態を破壊しない
- [x] タグ追加は重複・空白を無視し、削除は該当が無ければ同一参照を返す
- [x] 条件クリアはフリーワードと並び順を残す
- [x] 「絞り込み中」件数はフリーワード・並び順・ページを数えない／不正な分入力を数えない

## ランダム順（種つき）

`ORDER BY RANDOM()` はリクエストごとに引き直されるので、ページを繰ると同じ動画が
再登場したり抜け落ちたりする。UI は「ランダム」を選び直した時と「更新」を押した
時だけ種を引き直し、ページ送り中は同じ種を送る。

- [x] 種は `sortBy = 'random'` のときだけ送る
- [x] 種が未設定 (0) なら送らない（従来どおり `ORDER BY RANDOM()`）
- [x] `newRandomSeed()` は Rust 側の法に収まる正の整数
- [x] ページ送りでは種が保たれる
- [x] （Rust）同じ種ならページをまたいで重複・欠落なく全件辿れる
- [x] （Rust）同じ種の再実行は同じ順序
- [x] （Rust）種 0 / 法の倍数 / 負値 / `i64::MIN` でも全件返る
- [x] （Rust）種を変えると並びが変わり、DL 順のままにはならない

## スマートプレイリスト連携

- [x] オンライン検索に無い条件（解像度・ショート）は渡さない
- [x] ローカル専用の並び順は `smartPlaylists.normalizeFilter` 側で落ちる
- [x] オンラインでも使える並び順（`view_count` など）は残る
- [x] 保存できるのはキーワードかタグがある時だけ（投稿者 ID だけでは
      Snapshot Search の必須パラメータ `q` を組み立てられない）
- [x] 落ちる条件を列挙する（解像度・ショート・ローカル専用の並び順）
- [x] 投稿者の種別（`user` / `channel`）を引き継ぐ。種別不明なら渡さない
- [x] チャンネル投稿は `channelId`、ユーザ投稿・種別不明は `userId` で検索する
- [x] `uploaderType` は `uploaderId` とセットの時だけ保存される
- [x] 「最長 0 分」は `normalizeFilter` が捨てるので、落ちる条件として挙げる
      （「最短 0 分」はローカルでも無意味なので警告しない）
- [x] キーワードの対象範囲が変わる点（オンラインはタイトル/タグのみで
      保存コメントは対象外）を注意書きに出す
- [x] プレイリスト編集画面でも投稿者の種別を往復させる（開く → 保存で
      チャンネル指定が `userId` に化けない）。種別は編集画面から変更もできる

## コメント横断検索

- [x] 3 文字以上でだけ検索できる（`search_library_comments` の下限と一致）
- [x] サロゲートペアも 1 文字として数える（Rust の `chars().count()` と同じ）
- [x] （Rust）FTS5 構文文字を含む入力 (`foo-bar` / `AND` / `(paren` / `"quote` /
      `うぽつ OR ` / `a*b`) でもエラーにならず、本文の literal 検索になる
      — コメント検索と動画のフリーワード検索の両方
- [x] （Rust）`fts_phrase` は二重引用符で包み、内側の `"` を `""` に畳む
- [x] （Rust）包んでも保存済みコメントの部分一致は従来どおりヒットする
- [x] （Rust）検索対象は各動画の**最新スナップショットのみ**。再取得で
      スナップショットが増えても重複せず、旧版にしか無いコメントは出ない
      （「最新」の定義は `snapshots::list_snapshots` と同じ taken_at DESC, id DESC）
- [x] ヒット → 動画ページのリンクは vpos(ms) を秒へ落として `?t=` を付ける（負値/NaN は 0）
- [x] 動画 ID はエスケープする
- [x] `?t=` の解釈は秒へ丸め、未指定/不正値/負値は「頭出ししない」(`null`)
- [x] リンク生成と解釈が往復する

## 集計・候補のスコープ

- [x] （Rust）タグ集計 (`unique_tags` / `top_tags`) と候補一覧 (`list_all_tags`)
      は DL 済み動画 (`video_path IS NOT NULL`) に限る。ローカルファイルが
      外れた動画のタグを数えて「選んでも 0 件」の候補を出さない
- [x] （Rust）投稿者一覧はユーザ ID とチャンネル ID を別名前空間として扱う。
      数値が同じでも種別が違えば別行になり、種別ラベルも取り違えない
- [x] （Rust）`uploader_type` 指定つきの絞り込みは同じ ID の別種別を混ぜない。
      種別を指定しなければ従来どおり ID だけで引く
- [x] 投稿者セレクトは種別込みの複合キー (`user:123` / `channel:123`) を値にする
- [x] （Rust）`unique_uploaders` も (ID, 種別) で数える。`list_uploaders` の
      行数と一致し、絞り込みの粒度ともズレない
- [x] （Rust）`top_tags` の件数は **動画数**。`tags` の主キーは
      (video_id, name, source) なので、同じタグが別 source にも入っている
      動画を二重に数えない（チップの件数 = 実際に絞り込める件数）

## ページャ

- [x] 件数レンジ表記（`120 件中 49–96 件` / 0 件）
- [x] 総ページ数は最低 1
- [x] 総件数が減ったら最終ページへ丸める（範囲内なら同一参照）

## 検索条件の要約

- [x] 条件なし
- [x] 指定した条件だけを並べる（分の上限/下限/範囲）

## 永続化 (sessionStorage)

- [x] 保存した状態を復元できる
- [x] 未保存なら既定値
- [x] 壊れた JSON でも既定値へフォールバック
- [x] 古い / 改竄された値（不正な `sortBy`・範囲外の `pageSize`・型違いの `tags`）は正規化して読む
- [x] 投稿者が選ばれていない / 不明な種別の `uploaderType` は落とす
- [x] ランダム順の種は範囲外（負値・上限超え・非数値）を捨てる

## 手動確認（実データ）

`query.rs` / `videos.rs` の実コードを、実際の niconico から取得した動画メタ・
タグ・コメントで seed した SQLite に対して実行し、UI が送るクエリ形をひと通り
確認済み:

- 並び順 10 種（`downloaded_at` / `posted_at` / `title` / `view_count` /
  `mylist_count` / `comment_count` / `duration_sec` / `play_count` /
  `last_played_at` / `random`）
- ページング（`offset` = ページ × 件数で重複・欠落なし）
- タグ AND / 投稿者 / 解像度 / 再生時間 / ショートの各絞り込みと組み合わせ
- フリーワード（タイトル・タグ・コメント FTS のいずれでもヒット）
- 集計（本数・総再生時間・投稿者数・タグ数・よく付くタグ・解像度分布）
- コメント横断検索とそのページング
- ホワイトリスト外の `sort_by` は Rust 側で拒否される
- FTS5 構文文字を含む入力が literal 検索になる（修正前は SQLite エラー）
- 種つきランダム順のページ送りで重複・欠落が出ない

ライブラリ画面自体も同じ実データで描画し、絞り込み → 並び替え → ページング →
コメント検索 → リロード復元 → ランダム順のページ送り → コメントモードでの
集計チップ無効化 → 投稿者絞り込み（セレクト / カードのボタン）まで操作確認済み。
スマートプレイリスト編集画面についても、チャンネル条件を開いて保存し直しても
`uploaderType` が保たれること、編集画面から種別を変更できることを確認済み。
